# 배당 달력 (Dividend Calendar) 아키텍처 문서

> 버전: v0.3

## 1. 목표

- 관심 종목의 배당 일정(배당락일, 지급일, 배당금)을 자동으로 수집해 달력으로 보여준다.
- 종목을 누르면 배당 데이터에 근거한 AI 해설 한두 문장을 보여준다.
- LLM은 결정적 처리가 불가능한 영역(자연어 생성)에만 사용하고, 출력은 코드로 검증 가능하게 설계한다.

## 2. 전체 구조

```
[수집: 매일 1회]
Scheduler (@Scheduled)
   ▼
Fetcher
   ├─ 매일: FMP 배당 캘린더 API (한 달 범위, 하루 1~2회 호출)
   └─ 신규 종목 등록 시 1회: FMP 종목별 배당 이력 API
   ▼
Rule Validator (코드)
   ├─ 정상 → DB 저장 (upsert)
   └─ 오류 → 실패 기록 + Slack 알림

[조회: 사용자가 종목 클릭 시]
Insight 서비스
   ├─ 오늘 생성된 캐시 있음 → 그대로 반환
   └─ 없음 → 지표 계산(코드) → LLM 문장 생성 → 출력 검증(코드) → 캐시 저장
                                                   └─ 검증 실패 시 템플릿 문장으로 대체
```

## 3. 컴포넌트별 역할

**Scheduler**: 매일 정해진 시간에 수집을 시작한다. `@Scheduled`로 충분.

**Fetcher**: 외부 API 호출과 정규화만 담당. 판단 로직 없음. 타임아웃, 재시도 포함. 데이터 소스는 `DividendSource` 인터페이스로 추상화.

**Rule Validator**: 코드로 판단 가능한 검사. (근거는 `fmp-dividends-notes.md`)
- 날짜 순서: 배당락일 <= 기준일 <= 지급일 (2024년 5월 이후 T+1로 배당락일 = 기준일이 정상)
- 필수값(티커, 배당락일, 배당금) 누락 시 오류. 빈 문자열 날짜("")는 null
- 배당금 비교는 반드시 `adjDividend` 기준 (원본값은 액면분할 시 급변)
- 과거 대비 비정상 범위는 오류 대신 "확인 필요"로 기록 (특별배당 가능성)

**Insight 서비스 (AI)**: 5장 참고.

**알림**: Slack으로 오류 건을 알린다.

## 4. 데이터 흐름

- 최초 종목 등록 시: 종목별 이력 API 1회 → `dividend_histories`에 과거 이력 저장
- 매일: 캘린더 API로 새 배당 일정만 추가/갱신
- 해설 생성 시: DB 이력으로 지표 계산 (외부 호출 없음)

## 5. AI 기능 명세: 종목 배당 해설 (Dividend Insight)

### 원칙
- **숫자는 코드가 계산하고, LLM은 주어진 숫자로 문장만 쓴다.** LLM이 계산하거나 숫자를 만들어내지 않게 한다.
- **판단이 아니라 해석이다.** 매수/매도 추천, 목표가, 전망은 쓰지 않는다.
- LLM이 실패해도 서비스는 동작해야 한다 (템플릿 문장으로 대체).

### 입력 (코드가 계산해서 LLM에 전달)
| 항목 | 예시 |
|---|---|
| 티커, 종목명 | AAPL, Apple Inc. |
| 다음 배당락일 / 남은 일수 | 2026-11-09 / 12일 |
| 다음 지급일 | 2026-11-12 |
| 최근 배당금(adj) / 직전 대비 변화율 | 0.27 / +3.8% |
| 연속 증액 연수 | 5 |
| 현재 수익률 / 5년 평균 수익률 | 0.34% / 0.49% |
| 배당 주기 | Quarterly |

현재 주가, 밸류에이션 지표는 FMP 무료 플랜 가능 여부 확인 후 추가.

### 출력
```json
{ "comment": "한국어 1~2문장" }
```
Spring AI 구조화 출력으로 Java record에 매핑.

### 출력 검증 (코드)
1. 문장 속 숫자가 모두 입력값에 존재하는가 (환각 방지)
2. 금지 표현이 없는가: 매수, 매도, 추천, 사세요, 목표가, 오를, 떨어질 등
3. 길이 제한 (예: 150자 이내)

실패 시 1회 재시도 → 또 실패하면 템플릿 문장 사용.

### 캐시
- 종목당 하루 1회 생성. 해당 종목 배당 데이터가 바뀌면 무효화.
- 클릭할 때마다 LLM을 호출하지 않는다.

### 기록 (insight_logs 테이블)
입력값, 출력, 검증 결과, 재시도 여부, 토큰 수, 응답 시간을 남긴다.
→ 품질 지표: **검증 통과율, 템플릿 대체율, 평균 응답 시간, 일일 비용**

### 화면
해설 아래에 "투자 권유가 아닌 데이터 요약입니다" 문구 표시.

## 7. 한국 주식 추가 대비 원칙

- 테이블에 `market`(US/KR), `currency`(USD/KRW) 컬럼을 처음부터 둔다.
- 금액은 `NUMERIC` / `BigDecimal` (double 금지)
- 한국 주식은 나중에 `DividendSource` 구현체만 추가 (예: DART)
