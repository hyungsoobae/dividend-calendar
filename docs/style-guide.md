# Style Guide

> 이 문서는 사람이 읽는 컨벤션 문서이자, CodeRabbit이 리뷰 기준으로 참조하는 파일이다.
> (`.coderabbit.yaml`의 `knowledge_base.code_guidelines.filePatterns`)
> 규칙은 처음부터 다 채우지 않는다. 리뷰에서 반복되는 지적이나 반복되는 수정이 생기면 그때 한 줄씩 추가한다.

## 0. 프로젝트 전제

- Java 21, Spring Boot 4.1.x, Gradle (Kotlin DSL)
- PostgreSQL, Spring AI
- 테스트: JUnit 5, Testcontainers
- 설계 기준 문서: `docs/architecture.md`. 이 가이드와 충돌하면 architecture.md가 우선한다.

## 1. 원칙

- **결정적인 것은 코드로**: 검증·계산처럼 규칙으로 판단 가능한 로직은 코드로 구현한다. LLM은 결정적 처리가 불가능한 영역(자연어 생성)에만 쓴다.
- **가독성 우선**: 영리한 코드보다 다음에 읽는 사람이 바로 이해하는 코드.
- **테스트 가능성**: 분기와 데이터 변환이 있는 코드는 단위 테스트로 고정할 수 있게 설계한다.
- **관측성**: 장애 재현에 필요한 최소 정보만, 적절한 레벨로 남긴다.

## 2. Java / Spring 스타일

- 들여쓰기 스페이스 4칸, 라인 길이 120자 이하 권장.
- 네이밍: 클래스 PascalCase, 메서드·변수 camelCase, 상수 UPPER_SNAKE_CASE.
- **패키지는 도메인 기준**으로 나눈다 (`dividend`, `fetch`, `validate`, `insight`, `notify`).
  기술 계층(`service`, `util`)만으로 최상위를 나누지 않는다.
- **DTO·값 객체는 `record`**. 외부 API 응답 DTO도 record로 받는다.
- **Lombok은 엔티티에만** 사용한다. `@Data`처럼 getter/setter/equals/toString을 한꺼번에 여는 애너테이션은 쓰지 않고, `@Getter`, `@Builder`, `@NoArgsConstructor` 등 필요한 것만 좁혀 쓴다.
- Spring bean은 **생성자 주입**. 필드 주입(`@Autowired` 필드)은 쓰지 않는다.
- `Optional`은 반환값에만. 필드나 파라미터로 넘기지 않고, 받은 즉시 처리한다.
- `java.util.Date`, `Calendar` 대신 `java.time` (`LocalDate`, `Instant`).

## 3. 실패를 숨기지 않는다

- **조용한 대체 금지**: 파싱 실패, 잘못된 설정, 유효하지 않은 입력을 `now()`, 빈 문자열, `0` 같은 임의의 기본값으로 조용히 바꾸지 않는다.
  단, 외부 포맷상 의미가 정해진 변환(예: 빈 문자열 날짜 `""` → `null`)은 규칙으로 명시하고 테스트로 고정한다.
- **명시적 처리**: 진행 가능한 문제는 WARN 로그와 함께 스킵하거나 부분 처리하고, 데이터 정합성을 해치는 문제는 예외를 던져 호출자가 인지하게 한다.
- `catch (Exception e) {}` 같은 빈 catch, 예외를 삼키고 null을 반환하는 코드는 리뷰에서 지적한다.
- 실패해야 하는 입력은 단위 테스트로 고정해 회귀를 막는다.

## 4. 외부 API 연동

- 호출에는 **타임아웃과 재시도를 기본**으로 넣는다. 재시도 대상(타임아웃, 5xx)과 비대상(4xx)을 구분한다.
- 외부 호출과 정규화만 담당하는 계층에는 판단 로직을 두지 않는다. 검증은 별도 계층에서.
- 응답 필드는 항상 없을 수 있다고 보고 파싱한다. 외부 필드명과 내부 도메인 용어가 다르면 매핑 지점을 한 곳으로 모은다.
- 데이터 소스는 인터페이스로 추상화해 구현체를 교체할 수 있게 한다.

## 5. 비밀값

- API 키·비밀번호는 코드나 설정 파일에 직접 쓰지 않고 **환경변수로 주입**한다.
- 키가 쿼리 파라미터에 들어가는 API는 **요청 URL 전체를 로그에 남기지 않는다.**
- 로그·예외 메시지·테스트 픽스처 어디에도 실제 키를 넣지 않는다.

## 6. 데이터와 영속성

- 금액은 `BigDecimal` / `NUMERIC`. `double`, `float` 금지.
- 수집·저장은 **멱등**해야 한다. 같은 데이터를 다시 수집해도 중복이 생기지 않게 자연키 기준 upsert.
- 다국가 확장을 고려한 컬럼(`market`, `currency`)은 처음부터 둔다.
- 날짜는 어떤 날짜인지 이름에서 드러나게 한다 (`exDate`, `paymentDate`처럼).

## 7. LLM 연동 코드

- **숫자는 코드가 계산하고, LLM은 주어진 숫자로 문장만 쓴다.** 계산을 프롬프트에 위임하지 않는다.
- LLM 출력은 **코드로 검증한 뒤** 사용한다. 검증 실패 시 정해진 대체 경로(템플릿 등)로 빠지고, 서비스는 계속 동작해야 한다.
- 프롬프트는 코드에 흩어놓지 말고 한 곳에서 관리한다.
- 입력값, 출력, 검증 결과, 재시도 여부, 토큰 수, 응답 시간을 기록한다.
- 프롬프트나 모델을 바꾸는 변경은 무엇이 어떻게 달라지는지 PR 설명에 적는다.

## 8. 로깅

- 레벨: DEBUG(개발용 상세), INFO(주요 경로), WARN(정상 흐름은 아니지만 계속 처리 가능), ERROR(즉시 주의).
- 반복 호출되는 경로에서 INFO를 남발하지 않는다.
- 재현에 필요한 식별자(티커, 날짜, 작업 ID 등)는 포함하되 민감정보는 제외한다.
- 예외는 메시지만 문자열로 붙이지 말고 예외 객체를 함께 넘긴다.

## 9. 예외 처리

- 도메인별 예외 클래스를 두고, 호출자가 구분해서 처리할 수 있게 한다.
- 예외 메시지에는 원인 파악에 필요한 컨텍스트를 넣는다. 스택 트레이스는 서버 로그에만.
- 예외를 흐름 제어(정상 분기)로 쓰지 않는다.

## 10. 테스트

- 파서, 검증 로직, 저장소, 예외 처리처럼 분기나 데이터 변환이 있는 코드는 **단위 테스트 필수**.
- 버그 수정 시 재발 방지 테스트를 함께 추가한다.
- **경계값 테스트**: 잘못된 입력, 누락된 필드, 빈 값, 중복, 외부 포맷 변경을 포함한다.
- 시간, 파일시스템, 네트워크, 환경변수처럼 테스트에서 제어하기 어려운 값은 주입하거나 작은 어댑터로 감싼다. (`LocalDate.now()` 직접 호출 대신 `Clock` 주입)
- DB가 필요한 테스트는 Testcontainers. 외부 HTTP는 목 서버로 대체하고 실제 API를 호출하지 않는다.
- 테스트 이름은 "무엇을 했을 때 어떻게 된다"가 드러나게 쓴다.

## 11. Git / PR

- `main`은 항상 실행 가능한 상태. 작업은 `feat/내용` 브랜치에서 하고 PR로 병합한다.
- 커밋 메시지: `타입: 내용` (feat, fix, refactor, test, docs, chore), 내용은 한국어.
- 커밋은 의미 단위로, 빌드와 테스트가 통과하는 상태에서.
- 새 의존성을 추가할 때는 이유를 PR 설명에 한 줄로 적는다.
- 요청 범위를 넘는 리팩터링은 같은 PR에 섞지 않는다.

## 12. 리뷰 체크리스트

- [ ] `docs/architecture.md`의 설계와 동작이 일치하는가
- [ ] 실패를 조용히 기본값으로 대체하는 곳은 없는가
- [ ] 외부 호출에 타임아웃·재시도가 있는가
- [ ] 비밀값이 코드·로그·테스트에 노출되지 않는가
- [ ] 금액이 `BigDecimal`인가, 저장이 멱등한가
- [ ] 분기·변환 로직에 테스트가 있는가, 경계 케이스를 포함하는가
- [ ] 로그 레벨과 양이 적절한가
